## 1. Method (nothing simulated in the code under test)

* A **real** orchestrator output (`evidence/runs/T19B0_orch_run1.pipeline_output.json`, 342/342, margin 14.50 %) is the
  input of every consumer.
* **Backend**: the production module `backend/server.py` is imported in a snapshot that has that file at its root
  (the server loads `pipeline_output.json` from there) and driven through FastAPI's `TestClient`:
  `/api/metrics/summary`, `/api/regions/`, `/api/pipeline/iterations`; `backend/routes/metrics.py::_derive_metrics_from_pipeline`
  is called directly (tool: `evidence/tools/tier0_backend.py`).
* **Frontend**: the production runtime adapter (`normalizeRuntime`) and the production React components are bundled
  with the project's own `esbuild` and rendered server-side with `react-dom/server`; what a user would see is recorded
  (tool: `evidence/tools/tier0_frontend.mjs`; components: `SummaryView`, `RegionCard`, `RegionalIntelligence`,
  `OptimizationInsights`, `ExportPanel`, the whole console `CommandCenter` view, `BenchmarkBadge`).
* **Edge cases** that a real run does not produce are `derived_*` scenarios built from the real output by
  `evidence/tools/tier0_scenarios.py`: only the margin-driving numbers change, and the verdict text, the decision layer's
  margin fields and the margin band are **regenerated by the production functions** (`OrchestratorAgent._margin_report`,
  `_rule_based_explanation`, `canonical_network_economics`, `classify_margin`). They test how a consumer treats an edge
  value; they are labelled and are not evidence about the optimiser. Generated tables:
  `evidence/comparisons/tier0_consumer_tables.md`; raw: `evidence/outputs/tier0_*.json`.
